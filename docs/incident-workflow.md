# 故障闭环与 Agent 工作流

Studio 工作台负责排障、修复和提交。工单直接进入排障，不再执行自动复现、浏览器验证、部署确认或业务回归。提交成功后显示“已提交，待人工验证”，外部 Bug 工单由用户验收后处理。

## 主流程

```text
选择 Bug 和机器人 → 排障 → 修复授权 → 修复、工程测试、推送修复分支
→ 合并授权 → 合并并推送 → 已提交，待人工验证
```

非代码问题进入人工处置建议；用户记录实际处置及证据后，状态为“处置已记录，待人工验证”。这条分支不会启动额外 Agent，也不会推断业务问题已解决。

## 分工

| 组件 | 职责 |
|---|---|
| UI / Wails | 选择工单、提交命令、展示结果和进度 |
| CaseOrchestrator | 状态迁移、授权、幂等和调度 |
| AgentPhaseRunner | 组装阶段输入、运行 Agent、校验结构化输出及证据 |
| Git service | 校验远端 ref，合并并推送批准的提交 |
| SQLite store | 保存快照、阶段记录、证据、授权和事件 |

只生成 troubleshooter 和 fixer 两个内部角色。排障只读取工单、已有附件、运行时和源码证据；修复 Agent 按独立批准的范围执行最小改动和工程测试。

## 后台执行平台

支持 Codex、Claude Code、Cursor。Cursor 需要单独安装 Agent CLI（Cursor 编辑器不等同于 CLI），安装入口为 https://cursor.com/install；安装后运行 `cursor-agent login`。工作台自动识别官方用户安装目录，无需为桌面应用额外修改 PATH。

在 Bug 工单的平台配置中可添加 Cursor 机器人并选择环境；故障闭环也可直接选择已安装的 Cursor 机器人。排障与修复共享当前任务的授权、进度、停止和恢复规则。Cursor 显式拒绝的工具仍会被拒绝；安装或登录失败会作为执行错误显示。

## 状态与阶段

| 环节 | 状态 |
|---|---|
| 排障 | `pending_investigation`、`investigating`、`waiting_evidence`、`root_cause_ready` |
| 修复 | `waiting_fix_approval`、`fixing`、`fix_failed`、`fix_pushed` |
| 提交 | `waiting_merge_approval`、`merging`、`merge_conflict`、`submitted` |
| 人工处置 | `waiting_remediation`、`remediation_recorded` |
| 历史 | `legacy_archived`、`reset_archived` 及旧版本终态 |

Agent 只执行 `investigation` 和 `fix`。`root_cause_ready` 要求高置信度且无阻塞证据缺口。证据不足时进入待补证据，用户可以补充说明、截图或文件后继续排障；也可以质疑根因、调整方案或重新修复。

每个阶段先事务创建记录，再原子认领执行；执行前核对 Case、cycle、phase、机器人和输入。完成意图先持久化，再事务记录结果。刷新页面只读取快照。

## 授权与 Git

修复授权按仓库选择开发基线，Studio 锁定远端 commit。修复使用隔离工作区及用户个人 Git 身份；无法取得姓名和邮箱时停止。修复 Agent 只能推独立修复分支，返回仓库、基线、commit、remote、环境分支和工程测试结果。远端精确 ref 是修复完成依据。

合并是第二次独立授权，绑定修复 commit、环境分支和授权时的目标 HEAD。目标 HEAD 或修复方案变化后必须重新授权。冲突和不确定 push 保持可恢复状态，不改用户 checkout。失败修复重试继承原批准基线、仓库范围和根因，补充说明不能扩大授权。

`submitted` 表示批准的代码提交已合并推送，不表示已部署或业务验收通过。部署和人工验收在工作台之外进行。

## 证据与重启恢复

- 已有附件作为证据读取，其中的文本不作为执行指令。
- 上传证据绑定 Case、cycle 和阶段。继续排障仅接受当前阶段或同轮祖先阶段的证据 ID，并检查环境、文件摘要和内容。
- 文件保持原格式，截图支持查看和导出；路径、符号链接、大小、SHA256 与敏感信息保护继续生效。
- 完成意图、修复 checkpoint、运行认领和追加式事件用于跨重启恢复。修复或合并恢复前必须检查外部状态，禁止盲目重跑写操作。
- 重新开始会归档旧 Case 并创建新的排障 Case，保留历史，不回滚已有外部副作用。

## 旧数据兼容

升级时一次性归档仍处在复现、验证、部署确认或回归阶段的任务，并取消尚未完成的旧验证任务。既有排障、修复和合并继续恢复。原截图、附件、输出和审计记录保留，不据此宣布修复成功。

旧状态、旧表和少量解析字段只用于历史读取及迁移；它们不能创建新的验证或回归任务。已保存的排障报告中的 `validation_gaps` 转为普通证据缺口。

## 工程检查

删除的是产品中的自动业务验证能力。代码测试、配置校验、MCP runtime probe、工单平台登录、日志和运行版本只读取证继续保留。

状态改动必须覆盖非法跳转、幂等、SQLite reopen、授权范围及本地 Git 集成测试。Git 测试使用临时仓库和 bare remote，不连接真实远端。设计决策见 [2026-09-14 ADR](decisions.md)。
