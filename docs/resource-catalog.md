# 连接与资源目录

创建向导按“选择项目 → 运行方式 → 排障能力 → 确认并创建”组织。先确定仓库、服务和环境，再按需接入运行信息；连接不足时明确显示缺口。

## 排障能力

| 能力 | 使用方式 |
|---|---|
| 配置源 | 按实例管理连接、namespace、配置项和服务归属；不需要时保持未启用 |
| 数据库与缓存 | 自动发现或手动添加；一条连接可关联多个服务，手动连接在重扫后保留 |
| 日志与服务状态 | 接入日志、指标、Trace 和 K8s；可复用已配置的 Kuboard/one2all 连接 |

没有可选连接时可以跳过；已添加的连接必须补全并通过对应检查。仅勾选能力不代表可用。修改连接会撤销旧检查结果，恢复草稿后重新检查认证。

Grafana 集中展示 Loki、Prometheus、Tempo 候选：唯一候选自动填入，多候选手动选择；刷新保留有效选择，清除已失效数据源。桌面端必须成功读取数据源列表，健康接口成功不能代替账号权限检查。

## 资源身份

Schema 0.2 使用 `resource_catalog` 描述下列关系：

```text
仓库 / 子目录 → 服务 / 工作负载 → 环境
                              ├─ 分支与配置源
                              ├─ 数据连接
                              └─ K8s、日志、指标、Trace
```

- **repository**：代码仓库 URL、本地路径和子目录。
- **service**：业务服务身份，用于配置和数据关联。
- **workload**：运行时工作负载；前端也可独立声明。
- **source instance**：配置源实例，不能只按类型区分多个连接。

路由优先按环境和服务读取资源目录。旧 YAML 自动派生目录，无需手工改版本；配置源和数据连接使用稳定 ID，避免同类连接相互覆盖。

## 配置与凭据

普通预览、复制的 YAML 和浏览器草稿不保存真实 secret；桌面端通过系统钥匙串恢复凭据，部署时注入。显式“导出可部署配置”可能含真实凭据，不得提交版本库；缺少凭据时须补全。脱敏配置换机器导入后通常需要重新填写凭据。

配置源 Kuboard/one2all 与运行平台的连接复用必须进入最终 YAML；已有独立运行连接保留，工作负载从实际资源列表选择，不能凭配置文件名猜测。

## 边界

- Nacos、Apollo、Consul 支持按实例隔离；Kuboard、one2all 当前各只提供一个连接实例。
- 同一配置文件有多个同类型数据连接且扫描无法区分时，需要手动补录。
- 同环境且身份、字段完全一致的连接才合并展示，不按地址合并不同账号。
- 基础配置可用于源码排障；没有日志、数据或运行映射时，不能宣称具备对应的运行时证据。
