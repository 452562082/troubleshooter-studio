# 排障能力桌面验收记录

日期：2026-09-15。

## 方法与隔离

使用原生 Wails 桌面窗口实际点击、输入、检查和重启。验收副本使用独立应用标识、Bug 数据目录和用户配置路径；页面、桌面绑定、连接检查和钥匙串流程使用当前实现。测试项目为 `capability-acceptance-0915`，未部署该测试机器人，未覆盖用户原有创建草稿或机器人。

真实服务：本机 Redis，以及独立容器中的 Grafana 11.6.0、Prometheus 2.55.1。Grafana 数据源健康接口确认可以查询 Prometheus API。测试结束后关闭验收副本，停止 Redis、协议测试服务并移除两个临时容器和专用网络。

## 实际操作结果

| 场景 | 结果 |
| --- | --- |
| 无配置源时添加 Redis，并关联 orders、payments | 展示一条共享连接，关联两个服务 |
| Redis 地址不完整 | 待补充，不能继续 |
| Redis 使用未监听的端口 | 原生检查失败，显示连接异常，不能继续 |
| 将地址修正为真实 Redis | 编辑保持展开，旧检查失效；检查成功后两个服务通过 |
| 退出并重开桌面副本 | 草稿、连接字段和共享服务关系恢复；连接需要重新检查 |
| Grafana 使用正确测试账号 | 实际读取数据源，唯一 Prometheus 候选自动选中 |
| 增加第二个 Prometheus 候选后刷新 | 保留仍有效的原选择 |
| 删除原选择，并保留另外两个候选 | 清除失效选择，阻止继续，要求用户选择 |
| 手动选中有效候选 | 恢复可继续状态 |
| 将 Grafana 密码改错 | 数据源接口真实返回 401，页面显示账号或数据源检查失败，阻止继续 |
| 改回正确密码 | 自动重新发现，恢复账号与数据源可用 |
| 返回最终摘要，运行配置格式检查 | 进入摘要，显示两服务的 Redis；后端配置格式检查通过 |
| 添加 one2all 配置源 | 手动 Redis 连接保留 |
| 一键复用 one2all 到运行平台 | 无需重填凭据，自动带入唯一集群和命名空间，读取两个 Deployment |

one2all 场景使用本机 HTTP JSON-RPC 协议测试服务，要求匹配独立测试 Bearer Token，记录到 `platform_list_clusters`、`platform_list_namespaces`、`platform_list_configmaps`、`platform_list_deployments` 请求。这验证了实际桌面绑定和复用流程，不代表真实 one2all 业务平台或 Kuboard 已联调通过。

## 本次发现并修复

1. 连接填完整后，展开状态直接跟随校验结果而自动折叠。改为保留编辑展开状态；实际改地址复测通过。
2. Grafana 健康接口成功掩盖了数据源接口的认证失败。桌面继续条件增加数据源读取成功检查，凭据编辑和草稿恢复均不能沿用旧认证成功；错误密码与恢复场景复测通过。

自动化回归：63 个测试文件、627 项前端测试通过；类型检查及生产前端构建通过。新增覆盖包括编辑不中断、健康接口成功但认证未完成时阻断、修改或清空凭据使旧结果失效、缓存选择恢复但认证状态重新检查。
